## Reproduced cause and fix
The alpha-silhouette heuristic was guessing anatomical positions from hair/clothing outlines. On body10, knees were at 88% of picture height (lower shins/ankles), while visible knees were about 79–80%; a physical tap on the actual knee was marked as a leg. Eyes and seated hands/feet also drifted. The previous rapid-input test clicked generated hotspot centers, so it could pass with incorrect placement. A new test using the pictured knee failed before the fix.

`js/body-parts-data.js` now contains picture-specific landmarks checked against the original artwork. Resolution accepts only points inside actual mapped regions, handles nested regions such as knees within legs, ignores background/non-primary/right-button taps, and preserves once-only completion. Correct taps show an explicit positive message; repeated wrong input is bounded and two mistakes reveal helpful outlines. Keyboard answers use the same resolver. Failed images offer retry without an invisible quiz; page exits and restored pages retain timer/generation safeguards. Rotation avoids an unbounded random retry loop.

Questions are filtered to features shown in each picture. Covered ears/hair on body12 and cap-covered hair on body06 are omitted. Body03 has a transparent hole through its shirt/torso and is temporarily excluded from the rotation; its original asset remains unchanged for later replacement. Eleven drawings remain usable, including the seated child. The figure preserves the artwork's aspect ratio so coordinates remain aligned when the phone size changes.
